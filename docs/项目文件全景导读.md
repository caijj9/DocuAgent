# DocuAgent 项目文件全景导读

根据2026-10-29工作区当前源码整理。先建立文件地图，再逐段阅读后端代码。前端只标明文件用途，不展开前端语法。

“全部文件”分为两部分：开发者维护的源码、配置、测试、脚本和文档逐一列出；上传课件、构建依赖、日志、Git内部对象和实验克隆等运行产物按目录说明。最后的完整索引覆盖本次核对到的每个Git跟踪文件，不把不同时间戳的结果文件误当成不同业务模块。

## 1. 先理解目录与请求的关系

├── src/test/java/                     自动化测试
├── sql/                              数据库建表
├── scripts/                          Node.js评测与维护脚本

典型业务请求的方向：Controller → Service实现 → Mapper / Redis / 模型组件 → VO → Result。
当前CourseController直接使用CourseMapper，所以并非每个接口都经过Service。目录表达职责分工，实际调用要看方法体。

以下Java文件均位于`src/main/java/com/docuagent/docuagent/`，表中给出其相对包路径。

## 3. Spring MVC：全部HTTP入口

| 文件 | 具体作用 | 关键接口/方法 |
|---|---|---|
| `controller/HelloController.java` | 早期连通性与错误处理验证入口 | /hello返回固定启动提示；/test-error故意抛业务异常；/test-500故意抛普通异常；/test-chunk检查切块。/hello本身不验证数据库、Redis或模型是否可用 |

| `controller/DocumentController.java` | 课件上传与课件列表的入口 | POST /document/upload接收courseId和MultipartFile；GET /document列出课程资料；业务交给DocumentService |
| `controller/RetrievalController.java` | 单独查看和评测检索结果 | GET /retrieval/search；接收问题、课程、mode、fusion、rerank、topK，交给RetrievalService |

| `controller/QaStreamController.java` | 把已核准回答通过SSE分段发送 | POST /qa/stream；建立SseEmitter，在线程池中调用qa.ask，发送status/references/delta/done或error，并处理取消与异常 |
| `controller/LearningController.java` | 练习、答题和错题的入口 | GET /question/{id}；POST /question/generate；POST /answer/submit；GET /wrong-question |
| `controller/SessionController.java` | 会话管理入口 | POST /session新建，GET /session列表，DELETE /session/{id}删除；交给SessionService |
| `controller/UsageController.java` | 查询某次请求的模型用量 | GET /diagnostics/usage/{id}读取AiUsage快照；已淘汰的记录返回业务404 |

Controller中的`@GetMapping`、`@PostMapping`和`@DeleteMapping`负责路径匹配；`@RequestBody`把JSON转换成Java输入对象；`@RequestParam`取得查询/表单参数；`@Valid`触发DTO校验。Controller返回普通对象时，Spring MVC通常使用Jackson把它序列化成JSON。

SSE入口返回的是事件流，不能把它理解为“一次返回一个普通Result JSON”。其业务错误通过error事件表达。

## 4. Service：接口与真正执行的业务

接口约定“可以做什么”；实现类给出“具体怎样做”。Spring根据组件注册和注入关系提供实现对象。

| 文件 | 具体作用 | 关键内容 |
|---|---|---|
| `service/DocumentService.java` | 约定课件业务能力 | list、uploadDocument：列资料与上传处理 |
| `service/impl/DocumentServiceImpl.java` | 执行从上传到可检索的完整流程 | 检查课程和同名课件；检查扩展名；保存原文件；Tika提取；记录document；切块和写chunk；按批向量化；保存索引；处理FAILED和部分向量清理 |
| `service/RetrievalService.java` | 约定检索入口 | search统一接收问题、课程、检索方式、融合/重排开关和topK |
| `service/impl/RetrievalServiceImpl.java` | 组织检索、过滤和结果排序 | 参数及课程检查；从数据库取得仍有效的分块；向量检索、关键词检索、RRF融合、可选重排；返回前再次核对metadata、归属和正文 |
| `service/QaService.java` | 约定两种学习问答能力 | ask负责引用答疑；agent负责受控工具助手 |
| `service/impl/QaServiceImpl.java` | 组织一次答疑或工具对话 | ask读取会话、替换指代、检索、生成、校验引用和依据、最多修正一次、保存完整问答；agent注册工具并按真实结果组织记录/收藏回答；rewrite只替换指代；actionText排除否定分句 |
| `service/LearningService.java` | 约定题目和学习记录操作 | getQuestion、generate、submit、wrongQuestions、history、saveManual |
| `service/impl/LearningServiceImpl.java` | 执行出题、评分、幂等与错题累计 | generateRaw分题型请求模型；reviewQuestions复核来源和单选唯一性；全部校验后事务入库；submit区分本地选择题与模型简答；requestId重放/冲突；事务中锁题、保存记录、累计错题 |
| `service/SessionService.java` | 约定会话生命周期，并定义内部数据 | create/list/delete/open/complete/close；Turn表示一轮问答；Context携带会话ID、课程、历史和锁标识 |
| `service/impl/RedisSessionService.java` | 使用Redis实现会话业务 | Hash存元数据，List存最近6轮，ZSet存会话列表；open检查范围并取得锁，complete用Lua追加并裁剪，close校验令牌后释放锁 |

### 五个实现类分别解决什么问题

- DocumentServiceImpl解决“资料怎样进入系统”。
- RetrievalServiceImpl解决“问题应该取出哪些资料片段”。
- QaServiceImpl解决“怎样根据片段形成回答并保留引用”。
- LearningServiceImpl解决“怎样出题、批改，以及可靠记录学习结果”。
- RedisSessionService解决“上一轮对话怎样接到下一轮”。

DocumentServiceImpl不是一个大事务把文件、数据库、模型和JSON索引全部回滚。它用处理状态与失败清理协调这些资源。LearningServiceImpl的答题记录和错题累计则明确在同一个数据库事务内提交，两者不要混为一谈。

## 5. Spring AI、文档处理和检索辅助文件

| 文件 | 具体作用 | 关键内容 |
|---|---|---|
| `ai/StudyModel.java` | 对结构化模型调用做统一封装 | json组织system/user输入及模型选项；read严格解析JSON，拒绝重复字段和尾随内容；转换供应商/格式错误为业务错误 |
| `ai/StudyOutputValidator.java` | 检查模型产出，再构造业务数据 | questions检查题量、题型、答案、来源、评分要点；grade验证用户答案原文证据并算分；text/strings检查字段；Grade承载评分结果 |
| `ai/StudyAssertions.java` | 从检索到的课件中提取可选事实 | from生成事实ID到Assertion的映射，过滤不完整/缺少主语的动作片段；模型选事实，服务器构造判断式二选一 |
| `ai/StudyTools.java` | 提供三个真实可调用业务工具 | @Tool修饰searchCourseMaterial、readAnswerRecords、saveWrongQuestion；绑定课程和收藏许可；统一invoke记录参数/结果并限制调用次数 |
| `ai/chunk/SimpleChunker.java` | 把长文本分为有尺寸和重叠规则的窗口 | split按Unicode码点切分，避免把数学字符代理对切断；读取chunk.size、chunk.overlap |
| `ai/retrieval/RetrievalRanking.java` | 实现不依赖额外搜索引擎的排序算法 | terms提取术语；keyword做标题/正文命中打分；fuse按chunkId进行RRF排名融合；order负责稳定排序 |
| `ai/retrieval/BatchReranker.java` | 可选的聊天模型相关性重排 | rerank一次给候选打分；parse检查C编号是否完整、分数有界、JSON没有重复字段，再排序；当前默认关闭 |
| `ai/retrieval/DurableVectorStore.java` | 加强SimpleVectorStore的本地持久化 | 同步增删查与save；先写临时文件，再原子替换正式索引；不是新的Embedding模型 |
| `ai/verify/VerifyRunner.java` | Day0模型连通性验证入口 | 只在verify profile激活时执行聊天、Embedding、时间工具示例；正常启动不会自动跑这三项 |
| `ai/verify/ClockTools.java` | 演示@Tool确实能够执行Java方法 | currentTime输出调用日志并返回系统本地时间；city用于输入/展示，没有按城市切换时区的实现；不属于三个正式学习业务工具 |
| `ai/verify/ExportCorpusRunner.java` | 为分块调优导出真实课件语料 | 只在export-corpus profile激活；Tika读取有效课件，使用当前SimpleChunker产生分块，写本地JSON并关闭导出应用 |

项目有两个常见的Document含义：`entity/Document`是MySQL课件记录；`org.springframework.ai.document.Document`是送入向量库的文本与metadata对象。上传代码为后者写全限定类名，避免重名。

向量模型不是在StudyModel.json里调用的。VectorStoreConfig注入EmbeddingModel并交给向量库；DocumentServiceImpl调用vectorStore.add、检索代码调用similaritySearch时，会间接使用它。

实际答疑显式使用双路融合和qa.top-k；单独的/retrieval/search还有自己的默认mode/top-k。不能仅看到application.yml中retrieval.fusion-enabled=false就认定答疑没有融合。

## 8. Redis：文件之间如何配合

会话相关的主要代码集中在SessionController、SessionService、RedisSessionService、StudyRequests.SessionCreate与StudyViews.SessionView。它们已经在前面逐一列出，不需要为Redis另外寻找一个redis包。

```text
POST /session
  → SessionController.create
  → SessionService接口
  → RedisSessionService.create
  → Redis Hash、Sorted Set
  → SessionView

处理一条问答
  → QaServiceImpl.ask / agent
  → sessions.open读取历史、取得锁
  → 生成并处理回答
  → sessions.complete追加完整Turn、保留最近6轮
  → finally中的sessions.close释放自己的锁
```

SessionService.Context是Java内部传递的处理上下文，不是MySQL表。会话的课程绑定不是登录用户认证或多租户权限系统。

## 9. SSE、线程池和模型用量观测

SSE业务入口已经列在QaStreamController；工作线程池来自StreamConfig。回答先通过qa.ask完成校验，再由后台线程按Unicode字符发送。它不会改变QaServiceImpl的资料依据检查流程。

| 文件 | 具体作用 | 关键内容 |
|---|---|---|
| `metrics/AiUsage.java` | 在内存中维护每个请求的用量桶 | begin生成ID，bind/unbind维护当前线程关联，record累加聊天/Embedding调用及token，finish计时，get返回Snapshot，保留最近512个请求 |
| `metrics/UsageFilter.java` | 在HTTP请求进入业务前建立用量关联 | 设置X-Usage-Id，绑定当前线程，执行过滤器链，最后结束统计并清除ThreadLocal；跳过部分静态与诊断请求 |
| `metrics/UsageObservationHandler.java` | 观察Spring AI底层模型调用的实际响应 | onStart记住请求ID；onStop读取聊天/Embedding响应的Usage并交给AiUsage；不记录密钥或提示词正文 |
| `metrics/UsageConfig.java` | 注册可用的Micrometer ObservationRegistry | 当不存在注册表时创建，并装入UsageObservationHandler，让模型调用触发统计 |

配合顺序：UsageFilter建立请求ID → 模型观察器取得真实token → AiUsage汇总 → UsageController提供查询。

SSE在另一条工作线程运行，因此QaStreamController会把usageId绑定到工作线程，并在finally中解绑。只看HTTP入口线程的ThreadLocal，无法自动跨线程传递上下文。
