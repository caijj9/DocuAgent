# 段1：检索链路与可复跑评测

## 当前接口

`GET /retrieval/search`，统一响应 `{code,msg,data}`；沿用项目 HTTP 200、业务错误码表达失败的约定。

|参数|默认值|说明|
|---|---|---|
|q|必填|非空，最多1000字符|
|courseId|可选|指定后仅检索该有效课程；为空保留原版跨课程搜索行为|
|mode|vector|vector、keyword、both|
|fusion|false|仅both允许开启，采用RRF，k=60|
|rerank|false|必须同时mode=both、fusion=true；最多10条候选一次批量评分|
|topK|5|1到10；配置candidate-limit为候选上限，最多10|

示例（问题需URL编码，中文可在Apifox的Params中填）：

```text
GET /retrieval/search?q=正则表达式里r%2B是什么意思&courseId=1
GET /retrieval/search?q=词法分析&courseId=1&mode=keyword
GET /retrieval/search?q=词法分析&courseId=1&mode=both&fusion=false
GET /retrieval/search?q=词法分析&courseId=1&mode=both&fusion=true
GET /retrieval/search?q=词法分析&courseId=1&mode=both&fusion=true&rerank=true
```

`both&fusion=false` 返回两路各自topK的并列结果，最多2×topK，使用scoreType区分，未混排不同量纲的分数。
检索源同时校验course/document/chunk未删除，document状态DONE；向量metadata的课程、文档和正文也必须与数据库一致。孤儿向量不会占据最终topK。

## 分数解释

- vector_cosine：向量余弦相似度。
- keyword_coverage：中英文术语字面覆盖。中文双字片段，保留r+等符号术语；标题权重高，正文次数最多计3次。为少量资料采用Java打分，不声称实现BM25或MySQL中文全文索引。
- rrf：两路排名倒数融合，`Σ1/(60+rank)`；按chunkId去重，不按文档去重。
- llm_relevance_0_10：聊天模型对问题与片段的相关性评分，0到10。`rerankScore`同时保留此分数。模型一次批量处理最多10条，使用C0–C9标签避免编造数据库ID。

不同阶段分数不能直接比较大小。重排未能保证每个候选一个有效数值时返回业务码1008，不静默伪装成功，不把模型补充的文档作为引用。
未包含生成式答疑、拒答、会话记忆或工具调用；本段只完成检索链路。

## 真实课件评测

当前三份编译原理资料：引论、词法分析、语法分析。问题及答案锚点在 `eval/questions-v1.md`。
Q01–Q10作为固定初始集合，Q11–Q15为追加测试。需要改题或标准答案时创建新版本并保留原报告。

```powershell
node scripts/evaluate-retrieval.cjs
```

需要先启动18081后端，后端环境变量AI_API_KEY可用。该命令真实调用Embedding与批量重排，课件片段会发送到配置的硅基流动接口，可能消耗额度。
输出 `eval/baseline-v1.md`、按时间保存的 `eval/runs/*/results.json`、CSV和Markdown，每条包含top1分数、top3锚点相关性和耗时。
每次运行记录题目文件SHA256，失败项保留；中断运行也保留已完成的JSON记录。

```powershell
node scripts/evaluate-retrieval.cjs --ids=Q01,Q04 --phases=vector,fusion,rerank
```

指标分母不能混用：

- 7道可回答检索题：所有必要来源的原文锚点进入top5才算命中；跨文档题必须齐全。
- 3道课程隔离题：目标课程2目前为空，返回空才算通过；不能代替两个已填充课程的隔离测试。
- 3道无答案题：标pending_refusal，留给答疑阶段验证拒答，不计作当前已通过。
- 2道追问题：当前接口不接收history，原始追问仍会执行检索并记录命中，但标pending_history；不声称完成多轮理解。

自动原文锚点只是检索质量代理指标，不能证明最终回答质量。没有用不完整课件资料编造“15/15”。
成本尚未从供应商账单核对，未填入虚构数字。

### 2026-10-21真实运行结果

|阶段|可回答题的全部证据进入top5|空课程隔离|调用错误|
|---|---|---|---|
|仅向量|4/7|3/3|0|
|RRF融合|5/7|3/3|0|
|批量模型重排|5/7|3/3|0|

Q02（CFG四部分）由未找齐证据变为重排后找齐；Q10在融合后找齐；Q08三种方式都没有找齐跨文档证据；Q09反而在重排后丢失必要来源。保留这些失败，不声称重排必然更好。
三列总耗时分别约1.9秒、1.8秒、117.5秒，包含全部15题；批量重排主要成本在外部模型，默认仍关闭。
初次调试因模型漏编号而失败的明细保留在 `eval/runs/2026-10-21T01-38-04-830Z/results.json`；之后改为固定C标签和完整模板，最终45条调用全部成功。小样本结果不能作为泛化性能结论。

## 索引核对和修复

```powershell
node scripts/audit-index.cjs
```

该只读脚本从现有配置解析数据库连接，凭证仅经子进程环境传入，不写入快照或日志。课件快照、原文与向量候选均存放被Git忽略的data目录。
本机MySQL默认路径见脚本，可设置MYSQL_EXE覆盖；连接配置若需要环境变量，先在同一终端设置。不要把脚本输出的课程原文作为公开日志。

正确的一致性口径：

```text
有效课件数 = DONE且未删除、且所属课程有效的课件数
有效分块数 = 这些课件下面未删除分块数
有效向量数 = 有效分块数（逐ID、正文、课程和课件校验）
```

课件数不等于分块数。当前保留3份有效课件、115个有效分块；修复前152条向量中75条为孤儿，缺少38个有效分块向量；复用10个完全相同文本的旧向量，仅生成28条缺失向量，修复后115条全部一致。

修复操作先停止18081服务，再检查只读快照，然后运行：

```powershell
node scripts/repair-index.cjs
node scripts/repair-index.cjs --apply
```

无--apply只预览；--apply备份旧向量及数据库快照、保留所有数据库记录和上传文件、补齐向量并原子替换索引。脚本仅适用于此次已验证的BAAI/bge-m3/1024维旧索引，不是通用模型迁移工具。
旧索引与数据库快照在 `data/backups/2026-10-21T01-29-33-384Z/`。恢复旧索引也必须停止服务；旧备份本身含孤儿，不建议覆盖当前正确索引。

上传过程现在只有向量全部生成并持久化成功才标DONE；部分失败标FAILED并尽力清理本次向量，数据库状态过滤继续保护检索。单进程内串行上传、向量读写互斥和原子文件替换，不能当作多实例分布式一致性方案。
